# DOTween UI/FX Dependency

This document records the `UIW-17` DOTween dependency decision for the UI.Windows MVP FX migration.

## Source And Version

- Source: official Demigiant DOTween download page, `https://dotween.demigiant.com/download.php`.
- Imported archive: `https://dotween.demigiant.com/downloads/DOTween_1_2_825.zip`.
- Version: DOTween free `1.2.825`, published by Demigiant on 2026-02-13.
- Archive SHA-256 used for this import: `689d42944f7076038eb6b87ed4c85ae6951c4aec8eaae4e068524ce55b422c8c`.
- DOTween Pro was not imported.

The direct Demigiant ZIP was used instead of an interactive Asset Store import because it is an official Demigiant source and gives this repository a reproducible import path without requiring an editor login to the Asset Store.

## Setup Workflow

1. Download the official free DOTween archive.
2. Extract the archive into `Assets/Plugins/Demigiant/DOTween`.
3. Refresh Unity `6000.4.4f1` and request compilation.
4. Let DOTween setup/postprocessing create and save `Assets/Resources/DOTweenSettings.asset`.
5. Keep asmdef compatibility enabled so `Assets/Plugins/Demigiant/DOTween/Modules/DOTween.Modules.asmdef` exists.
6. Add project-owned UI assembly references only where UI/effects code needs them. `UiWindowsMvp.SampleSceneWindows` references `DOTween` and `DOTween.Modules` for future UI FX work.

Current module settings keep Unity UI shortcuts enabled:

- `uiEnabled: 1`
- `uiToolkitEnabled: 0`
- `textMeshProEnabled: 0`
- `epoOutlineEnabled: 0`
- `createASMDEF: 1`

## Generated Files

- `Assets/Plugins/Demigiant/DOTween/**`: official free DOTween runtime, editor helper, modules, readme, and Unity `.meta` files.
- `Assets/Plugins/Demigiant/DOTween/Modules/DOTween.Modules.asmdef`: DOTween-generated module assembly definition used by project asmdefs.
- `Assets/Resources/DOTweenSettings.asset`: DOTween settings generated by Unity setup.
- `ProjectSettings/ProjectSettings.asset`: DOTween setup-generated `DOTWEEN` scripting define for Unity build targets.
- `Assets/Scripts/UiWindowsMvp/Runtime/SampleSceneWindows/DOTweenMvpFxSmokeCheck.cs`: minimal project-owned compile smoke for Unity UI tween access.
- `Assets/Scripts/UiWindowsMvp/Tests/PlayMode/DOTweenMvpFxSmokeTests.cs`: targeted smoke test.

## Usage Boundary

DOTween is allowed only in UI/effects rendering code, primarily under `Assets/Scripts/UiWindowsMvp`.

DOTween types must not appear in `Assets/Scripts/ProjectContext` public domain/model ports. Domain/model services should continue to expose state, commands, and effect requests through project-owned ports without depending on `DG.Tweening`.

DOTween does not replace UI.Windows lifecycle ownership. Windows still open and close through `WindowSystem.Show`/`Hide` or narrow wrappers around those APIs. Future presenters/views that create tweens must kill or complete active tweens on hide, pool return, and final disposal as appropriate.

`UIW-11` applies this boundary to the migrated hints and FX slices:

- `UiHintsView` owns and kills its active hint sequence through `ClearHint()`.
- `UiFxView` owns collect/spend sequences, returns active items to its local pool, and kills active sequences through `StopAllFx()`.
- `UiHintsPresenter` and `UiFxPresenter` subscribe to request streams only in show scope and clear active animations on hide.
- `ProjectContext.UiRequests` and `ProjectContext.Player` expose/request FX data without `DG.Tweening` types.
